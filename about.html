How this page came to exist

This site was built by an automated pipeline called ai-app-factory, working from a plain-English request made in a different repository. If the word “factory” means nothing to you: it's a set of scripts and unattended Claude Code runs that turn a request into a provisioned repo, a working site, and a record of who approved what along the way. Below is that record, step by step, for this exact page.

  1. The ask. The requester, @mmorrow2012, opened intake issue mmorrow24work/ai-app-factory#41 asking for a simple hello-world site to test the ai-app-factory build process.
  2. Design doc drafted. The pipeline read that issue and wrote a design document proposing what this repo should contain and how it should be built — no human in the loop for the drafting itself.
  3. Design doc approved. The repo owner, @mmorrow24work, merged the design-doc pull request in ai-app-factory — the first of two deliberate approval gates before any of this repo's own automation runs.
  4. This repo provisioned. The pipeline created this repository from the approved design and minted it a scoped access token, with no human action needed.
  5. Milestones and issues seeded. The repo owner triggered this repo's own seeding workflow by hand — the second approval gate — which then read the design doc and filed the milestones and issues that describe this site, unattended.
  6. Each issue implemented. For every issue labeled claude-go, the pipeline wrote the code and opened a pull request against this repo — again, no human in the loop.
  7. Each PR reviewed and approved. The requester, @mmorrow2012, reviewed each resulting pull request and approved it from their own GitHub account.
  8. Merged. Once approved, the pipeline merged the pull request automatically.
  9. Deployed. Every push to main is published to GitHub Pages by the pipeline, with no human action needed — that's how this exact page reached you.

One step in that chain is still manual, and it's the only thing a human does entirely by hand here: nothing yet notifies the requester that a PR is waiting, so to approve or reject one, @mmorrow2012 has to know it exists and construct the approve/reject issue's URL themselves. The workflow that would open that issue automatically doesn't exist yet.
